# The Pan-India Route Template — design

**Date:** 2026-08-05
**Status:** approved, ready for planning

## Why

The site currently tells one ride as a finished story. The ride was never meant to be
only that: the itinerary behind it was distilled from ride reports on the xbhp forums
and Facebook touring groups, and drawn as a **loop anyone could run** — a Dakar-style
route book with fixed waypoints and two crossing points, Bangalore and Delhi, where
riders join or leave.

The planned loop was not ridden as drawn. Political tension in the Northeast closed
sections; weather windows for Ladakh and the Northeast do not overlap. The ride flexed
and still worked, and that is the strongest argument for the template being a template:
it survived contact with reality.

This work adds the template to the site as a first-class artifact, makes it downloadable
as a route book, and replaces the hero's "see the clips" with an animated overview of
the route.

## What exists today

- `index.html` — 1,667 lines, the entire site. Vanilla JS, no npm dependencies, no build
  step. Netlify publishes the repo root. It does make two kinds of external request:
  Google Fonts in the `<head>`, and OpenStreetMap tiles when the real-map toggle is on.
  "No external requests" in the README refers to the *map data* — basemap and route are
  baked in — not to the page as a whole.
- `route.json` — generated by `build-route.cjs` from the trip expenses sheet. 74 stops,
  93 nights, 29 regions, per-stop `stayCost`/`spend`/`link`, `totals.spend` = ₹341,402.
- `basemap.json` — Natural Earth outlines from the `_ind` point-of-view file, baked in
  by `build-basemap.cjs`. The atlas draws it with a hand-rolled Mercator fit.
- `manifest.json` / `tags.json` — the 222 clips.
- **Not in the repo:** `Pan India Trip  - Itinerary.csv` — 97 hops, origin/destination
  with coordinates, distance and duration per hop. This is the template's source.

Both source spreadsheets live outside the repo by existing convention. The template CSV
carries no private data (no accommodation, no spend), but it stays outside the repo
anyway so that all generators are fed the same way.

## Data model

### `template.json`, generated by `build-template.cjs`

```
node build-template.cjs "/path/to/Pan India Trip  - Itinerary.csv"
```

Same shape of contract as `build-route.cjs`: read a sheet, resolve derived structure,
write one JSON file that the page consumes. No network calls — the CSV already carries
coordinates for every waypoint.

```jsonc
{
  "generated": "…",
  "source": "Pan India Trip  - Itinerary.csv",
  // 98 places in sequence, 94 unique — Bengaluru, Delhi, Leh and Ladakh recur.
  "totals": { "hops": 97, "km": 18181, "hours": 412, "waypoints": 94, "countries": 3 },
  "crossings": [ { "name": "Bengaluru", "hops": [4, 93] },
                 { "name": "Delhi",     "hops": [23, 42] } ],
  "sectors": [ { "id": "S0", "title": "Southern opener", "from": "Trivandrum",
                 "to": "Bengaluru", "hopFrom": 0, "hopTo": 4,
                 "km": 1130, "hours": 22, "opensAt": null, "closesAt": "Bengaluru",
                 "stages": [ … ] } ],
  "hops": [ { "n": 0, "from": "Thiruvananthapuram", "to": "Kanniyakumari",
              "km": 95.1, "hours": 2.68,
              "fromLat": …, "fromLon": …, "toLat": …, "toLon": … } ]
}
```

**Sector boundaries are derived from the crossings, not hardcoded.** The script scans
the hop list for arrivals at Bengaluru and Delhi and cuts there. The one sector too long
to be a single unit (Delhi → Bengaluru, 51 hops) is subdivided into three stages at
declared hop indices at the top of the script, in the same style as `build-route.cjs`'s
`SKIP_NIGHTS` and `ORIGIN` constants.

Derived structure, verified against the CSV:

| id | title | run | hops | km | riding h |
|---|---|---|---|---|---|
| S0 | Southern opener | Trivandrum → **Bengaluru** | 5 | 1,130 | 22 |
| S1 | West coast & Kutch | **Bengaluru** → **Delhi** | 19 | 3,643 | 74 |
| S2 | Himalayan out-and-back | **Delhi** → **Delhi** | 19 | 2,742 | 62 |
| S3a | Gangetic plain & Nepal | **Delhi** → Phuentsholing | 16 | 2,801 | 64 |
| S3b | Bhutan & the Northeast | Phuentsholing → Agartala | 21 | 3,000 | 81 |
| S3c | East coast home | Agartala → **Bengaluru** | 14 | 4,154 | 92 |
| S4 | Closing run | **Bengaluru** → Trivandrum | 3 | 711 | 16 |

S3a/S3b/S3c are stages of one crossing-bounded sector (Delhi → Bengaluru); S0–S2 and S4
are each a single stage.

**Known discrepancy:** the sheet's own total row reads 18,039.2 km; summing the hops
gives 18,181.3. The difference is in the Agartala → Kolkata row, which the sheet records
as 1,523 km / 1 day 13 hours — the long way round rather than a rideable day. The
generator uses the summed figure and the site states it as ~18,200 km. The script warns
on any hop over 800 km so this stays visible rather than silently absorbed.

### Curated content, hand-authored

`template-notes.json`, edited by hand, keyed by sector and waypoint:

- **POIs** — seeded from waypoints that are self-evidently the destination (Dholavira,
  Khardung La, Paro Taktsang, Gandikota, Golden Pagoda, Hemis, Narayan Sarovar,
  Dhordo). Every other waypoint gets an empty entry for the author to fill.
- **Season and permit notes** per sector — the riding window and what paperwork gates
  it. Seeded with: Manali–Leh open roughly June–September; Inner Line Permits for
  Arunachal, Nagaland and Mizoram; Bhutan permits issued at Phuentsholing; Nepal entry
  at Sonauli with a carnet or bike papers; Rajasthan and Kutch unrideable in May–June
  heat. **Flagged for the author's review before publication** — these are the claims a
  reader would act on.
- **Sourcing** — the xbhp / Facebook attribution line. Left as an explicit placeholder;
  not to be invented.

The build script fails loudly if `template-notes.json` is missing rather than silently
publishing a route book with no seasons in it.

## Site changes

### 1. Shared atlas renderer — `atlas.js`

The map-drawing code currently lives inside the IIFE in `index.html`. `booklet.html`
needs the same drawing, and `index.html` is already 1,667 lines. Extract the renderer to
`atlas.js` exposing a small surface:

```js
Atlas.create(svgEl, basemap, { width, height, pad })   // → instance
  .drawRoute(points, { class })      // a polyline through lat/lon points
  .drawMarkers(stops, { onSelect })  // clustered at 3.5px, nearest-hit resolution
  .focus(bounds, { animate })        // viewBox easing, for the overview
```

Boundaries: `atlas.js` knows projection, clustering and hit-testing. It knows nothing
about legs, clips, narration or costs. `index.html` and `booklet.html` both consume it.
This is the only refactor in scope — no unrelated cleanup of `index.html`.

The existing clustering rules and the nearest-marker hit resolution move across intact.
They exist for documented reasons (a pixel is ~8 km at this scale) and must not be
re-derived.

### 2. The template section — `#template` in `index.html`

A full-width block after the legs column, before the closing section.

- **The pitch.** What this is: a route book, not a diary. Distilled from ride reports.
  Meant to be forked.
- **At a glance.** ~18,200 km · 97 legs · 412 riding hours · 3 countries · 2 crossings.
- **The five sectors**, each showing run, distance, riding hours, and which crossing
  opens and closes it. Expanding one reveals its stage-by-stage waypoint table with
  per-hop distance and duration, and its POIs and season note.
- **Join here.** Bengaluru and Delhi called out explicitly, with what each opens: from
  Bengaluru, S1 onward; from Delhi, the Himalayan out-and-back as a self-contained
  three-week ride that returns you to where you started.
- **Planned vs ridden.** See below.
- **What it costs.** See below.
- **Download the route book** → `booklet.html`.

### 3. Planned vs ridden

The atlas gains a **route overlay toggle**, orthogonal to the existing outline/real-map
toggle: the template line drawn ghosted beneath the solid ridden line. The gaps are the
argument — Nepal, Bhutan, Arunachal, Nagaland, Mizoram drawn and not ridden, against a
Northeast reached as far as Guwahati.

Alongside it, a short honest panel: which sections closed and why (political tension in
the Northeast), why the weather windows do not overlap, and what changed as a result.
Written from what the author states, not inferred from the data.

Toggle state persists in `localStorage` alongside the existing map-mode preference.

### 4. Costs, derived from what was actually paid

No invented rates. Everything comes from `route.json`:

| observed | value |
|---|---|
| total, 93 nights | ₹341,402 |
| accommodation | ₹135,448 — ₹1,456/night, median stay ₹1,433 |
| everything else | ₹205,954 — ₹2,215/night |

Those observed rates project onto each sector's nights and kilometres to give a per-
sector estimate. Presented as **what one rider paid in early 2025**, dated and
attributed, never as a quote or a forecast. The projection method is stated in the UI in
one line, not buried.

Nights per sector are estimated from riding hours at a stated hours-per-day assumption
(declared as a constant, shown to the reader), because the template has no night count
of its own — it is a route, not a schedule.

### 5. `booklet.html` — the downloadable route book

A standalone paged page, print-first, sharing `atlas.js`, `template.json`,
`template-notes.json` and `route.json`. Readable on screen; laid out for A4.

Structure:

1. Cover — title, ~18,200 km, three countries, the loop drawn.
2. The loop at a glance — totals, the five sectors, the two crossings, how to join.
3. Master map, full page.
4. One spread per sector — map inset showing that sector highlighted in the whole,
   waypoint table (from → to, km, hours), POIs, season and permit note.
5. Accommodation and cost breakdown.
6. Riding-season calendar — which sector in which months, and why they conflict.
7. Planning pages — blank night-by-night grid and a checklist.
8. "This is a template" — how to fork it, what the author changed and why.

Print mechanics: `@page` A4 with margins, `break-inside: avoid` on tables and cards,
`break-before: page` between sectors, colour-adjust forced so the map prints. The
"Download booklet" button calls `window.print()`. Screen and print share one stylesheet
with a `@media print` block, so what is on screen is what prints.

**The site's actual palette is dark, not the light `modernist` system the README still
describes.** The live tokens are `--color-bg: #0f0f0f`, `--color-text: #ffffff`,
`--color-accent: #8b5cf6`, `--color-accent-2: #ec4899`, in Space Grotesk with IBM Plex
Mono for figures. The booklet carries those on screen so it matches the site.

That makes print a deliberate inversion, not a pass-through: `@media print` flips to
paper (#fff) and ink (#111), turns the accent into something that survives a mono
printer, and drops the atlas's dark landmass fill for a hairline outline. A full-bleed
#0f0f0f page is not printable and must not be what `window.print()` produces.

The README's design-system section is stale on this point and gets corrected as part of
this work.

### 6. The overview

Replaces `SEE THE CLIPS →` on the hero with `SEE THE OVERVIEW ▸`. A quiet secondary link
to the clips remains, so the existing path is not removed.

It plays **in place**, not as a takeover. On ≥1080px:

- The route line draws forward and markers light in travel order.
- The atlas eases its viewBox toward the active region (`Atlas.focus`).
- The legs column scrolls in sync with the active region.
- A caption panel below the map cross-fades: leg title, the stretch, distance, dates,
  and a line of story.
- Controls: play/pause, chapter dots for the five legs, skip, exit.

Below 1080px the map is not sticky, so the overview becomes a full-viewport player —
map above, caption below — advancing the region chips rather than scrolling the
accordions.

`prefers-reduced-motion`: jump-cuts between legs, no viewBox tweening, no auto-scroll.
The overview remains fully usable as a stepper.

**Narration audio.** Text captions ship now. The audio path ships as plumbing only: each
leg may carry `narration: "media/narration/leg-01.m4a"`. When the file exists the
overview offers a speaker toggle, muted by default and off unless the listener asks.
When it does not exist, nothing appears and nothing errors. Recording five tracks later
lights it up with no code change. No speech synthesis.

Autoplay rules make this safe: nothing plays without a gesture, and the overview is
entered by a click.

## Testing

No test framework exists in this repo, and this design does not add one — it is a static
page with generated data. Verification is:

- **Generator** — `build-template.cjs` asserts its own invariants and fails loudly:
  hop count 97, summed distance within 1% of 18,181 km, every sector boundary landing on
  a crossing, no waypoint missing coordinates, `template-notes.json` present. Warnings
  for any hop over 800 km.
- **Data** — sector totals in `template.json` re-summed from `hops` must match the
  table in this document.
- **Print** — `booklet.html` checked in Chrome's print preview at A4: no orphaned table
  rows, no sector spread splitting mid-table, map visible.
- **Overview** — walked end to end at ≥1080px and <1080px, with `prefers-reduced-motion`
  forced on, and with narration files both absent and present.
- **Existing behaviour** — the clip grid, lightbox, region strip, map card and both map
  toggles still work after the `atlas.js` extraction. This is the main regression risk.

## Out of scope

- Any change to how clips, tags or the manifest work.
- Server-side PDF generation, npm dependencies, or a build step. The repo stays
  dependency-free.
- Route data for rides other than this one. The template is a template because it is
  documented and forkable, not because the site becomes a route-hosting platform.
- Recording the narration audio.
